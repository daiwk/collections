## 一、视频主题

**主题：从 Transformer 到现代 LLM：Attention 技术如何一步步演进？**

目标时长：5–7 分钟。

视频语言：简体中文。

目标观众：了解神经网络和 Transformer 基础，但不是专门研究 Attention 架构的技术爱好者与工程师。

1. 为什么早期 Transformer 需要 Multi-Head Attention？
2. MHA 在大模型推理中产生了什么瓶颈？
3. MQA、GQA 是如何缓解 KV Cache 问题的？
4. FlashAttention 解决的为什么主要是 IO 问题，而不是简单减少计算？
5. MLA 如何进一步压缩 KV Cache？
6. 这些技术如何共同推动现代 LLM 更高效地运行？

注意：这些技术并非完全线性的替代关系。必须准确区分架构改造、KV 表示压缩和 Attention Kernel 优化，解释哪些可以组合使用。

## 二、先进行技术研究

在制作任何视频之前：

1. 搜索并阅读相关原创论文和官方技术资料。
2. 建立关键技术时间线，标明论文首次公开的年份。
3. 提取每个技术的核心创新、解决的问题及代价。
4. 特别核对 MHA、MQA、GQA、FlashAttention、MLA 的差异。
5. 对有争议或存在条件限制的性能结论注明适用条件。
6. 生成 research.md，列出论文链接、核心结论和引用来源。

不要编造论文结论、性能提升倍数或年份。

## 三、叙事设计：不要做论文总结

视频需要像一个优秀的技术纪录片，而不是学术汇报。

采用以下叙事结构：

**第一幕：问题出现**

以一个直观问题开场：

“为什么模型越来越强大，回答问题却越来越吃显存？”

用一个不断增长的 KV Cache 动画引出问题。

**第二幕：技术进化**

从 MHA 的直觉解释出发，逐步引入 MQA、GQA。

每出现一种新技术，必须回答：

- 之前的设计有什么问题？
- 新技术修改了什么结构？
- 为什么这样修改有效？
- 损失了什么，或者引入什么权衡？

再解释 FlashAttention 和 MLA，强调它们针对的是不同层面的瓶颈。

**第三幕：现代架构**

将几种技术放到同一张对比图中，帮助观众理解它们的关系。

**第四幕：总结与展望**

讨论未来 Attention 设计可能继续优化的方向，明确区分已被验证的技术与研究趋势。

整支视频要有持续的故事推进，而不是按论文顺序逐篇介绍。

## 四、最重要：视觉表达

本项目的核心是 **Visual Explanation**，而不只是 Motion Graphics Decoration。

每讲一个重要概念，都必须使用真正解释原理的动画。

例如：

### 解释 Multi-Head Attention

- 把输入序列表示成多个可视化 Token。
- 通过流动的向量、连接线和矩阵展示 Q、K、V 的变换。
- 用不同颜色区分多个 Attention Head。
- 让观众直观看到每个 Head 分别计算 Attention。
- 最后通过真实动画展示多头结果的拼接与输出投影。

### 解释 MQA / GQA

- 从 MHA 的多个独立 K/V Head 开始。
- 逐渐将 K/V Head 合并或分组。
- Q Head 保持多个。
- 同步展示 KV Cache 所需存储量的变化。
- 用动态画面对比 MHA、MQA、GQA。

### 解释 FlashAttention

- 展示传统 Attention 对 HBM 访问的方式。
- 可视化分块计算、片上 SRAM 和 HBM 之间的数据移动。
- 展示 Online Softmax 的核心思想。
- 重点通过数据流动而不是文字解释 IO 优化。

### 解释 MLA

- 展示传统 KV 表示。
- 将其投影到低维潜在表示。
- 可视化低维 KV 缓存以及推理时的计算流程。
- 解释与 RoPE 相关的处理，不要错误地把 MLA 描述成简单低维压缩。

要求每个核心知识点都有至少一个持续 8–20 秒的精心设计的解释动画，而不是静态图片配旁白。

## 六、制作流程

请分以下阶段完成。

### Phase 1：研究与剧本

生成：

- research.md：事实核查与论文资料。
- script.md：完整中文旁白稿。

- 摄像机如何运动。
- 这个镜头帮助观众理解什么。

不要在研究完成前直接开始编写动画。

### Phase 2：关键镜头原型

先从整个视频中挑选三个最有技术难度的镜头：

1. MHA 到 GQA 的结构变化。
2. FlashAttention 的 HBM/SRAM 数据流。
3. MLA 的 KV 压缩和计算关系。

分别制作 10–20 秒的动画原型，实际渲染成 MP4。

抽取关键帧检查：

- 技术表示是否正确。
- 图形是否有重叠、裁切。
- 动画是否足够直观。
- 美术水平是否统一。
- 有没有退化成 PPT。

如果质量不够，请主动修改，而不是降低制作目标。

### Phase 3：正式制作

建议采用：

- Remotion：视频时间轴、场景合成、字幕。
- Three.js：三维矩阵、空间结构与摄像机动画。
- SVG/Canvas：向量示意图、曲线和图表。
- FFmpeg：视频合成及导出。

根据具体镜头选择适合的技术，不强制所有镜头使用 3D。

所有动画必须由确定的时间轴控制，以保证可重复渲染，不要依赖无法复现的随机动画或浏览器实时帧率。

### Phase 4：配音与音效

优先使用自然的中文配音。

如果本地没有高质量 TTS 服务，请预留标准化的音频接口与配音文件路径，不要使用明显机械化的配音充当最终成品。

旁白应该像优秀的中文技术科普 UP 主：

- 自然、有情绪、有节奏。
- 不朗读论文。
- 不堆砌术语。
- 重要知识点适当停顿。
- 旁白速度与动画保持同步。

加入适量音效，但不能干扰理解。

### Phase 5：质量验收

实际渲染出视频后，进行以下检查：

1. 关键论文、公式和技术解释是否正确。
2. 每个技术概念是否有有效的视觉解释。
3. 动画是否流畅、有层次、有精心设计的转场。
4. 文字是否重叠、裁剪或超出安全区域。
5. 配音、字幕、画面是否同步。
6. 全片视觉语言是否统一。
7. 是否存在明显低质量镜头。

请使用可用的截图、帧抽取和视频检查工具进行验证，不能仅凭代码运行成功就宣布质量合格。

- Dense FFN 和 MoE FFN 的区别。

- Total Parameters 与 Activated Parameters。

- Expert Load Balancing。
- 稀疏激活为什么可以减少每 Token 计算量。

### Chapter A：为什么传统 Attention 昂贵？

展示序列长度不断增长。

通过二维 Attention Matrix 让观众观察计算需求随序列长度增长的变化。

然后展示 KV Cache 和显存访问的开销。

必须区分：

- Prefill 的计算复杂度。
- Decode 阶段的状态存储。
- Memory Bandwidth。
- Attention 计算。
- 长上下文外推与训练上下文长度。

### Chapter B：Qwen3-Next 的 Gated DeltaNet

从标准 Attention 结构开始。

逐渐引出：

Gated DeltaNet

用状态随 Token 更新的动画解释其核心思想。

必须展示：

- 输入 Token。
- Recurrent State。
- 状态读取和写入。
- Gate 如何控制信息更新。
- 与显式 KV Cache Attention 的差异。

绝不能简单说 Gated DeltaNet 就是“给 Attention 加一个 Gate”。

根据官方论文和实现，准确表达它的状态更新机制。

### Chapter C：Hybrid Attention

展示 Qwen3-Next 中不同类型层的组合。

一些层使用 Gated DeltaNet。

另一些层使用 Gated Attention。

让摄像机从单个 Transformer Block 拉远，展示不同层在整个网络中的排列。

解释：

为什么线性/递归状态结构和标准 Attention 可以互补？

它们分别擅长什么？

为什么需要保留部分显式 Attention？

其局限又是什么？

### Chapter D：High-Sparsity MoE

介绍 Qwen3-Next-80B-A3B。

通过同一组专家网络对比早期 MoE 和高稀疏 MoE。

重点解释：

- 80B Total Parameters。
- 3B Activated Parameters。
- 更细粒度的专家。
- 激活比例和计算效率。
- 负载均衡及部署代价。

随后展示 Multi-Token Prediction（MTP）。

# 四、视觉美术：这次要比常规科普动画更精致

总体风格：

**Vox × 3Blue1Brown × 高级 3D 技术纪录片 × 现代 Motion Design**

这是风格方向，不允许直接复刻已有作品。

### 核心视觉原则

使用一套统一的 Transformer 3D Visual Language。

例如：

- Token：精致、可辨认的发光实体。
- Attention：动态连接和矩阵交互。
- FFN：具有层次的计算结构。
- MoE Expert：一组可激活的独立计算模块。
- Router：动态路径分配机制。
- KV Cache：沿序列时间轴增长的数据存储结构。
- Latent Vector：高维表示经过压缩后的可视化形态。
- RL：生成分支、奖励反馈、策略更新。
- mHC：多信息通道与受约束的变换结构。

以上仅是视觉隐喻，具体数据流和拓扑必须与真实算法一致。

每个模型迭代都应尽可能通过同一空间结构的连续变形来完成。

例如：

普通 FFN
→ 分裂成多个 Experts
→ 加入 Router
→ 加入 Shared Experts
→ 扩展专家规模

再例如：

MHA
→ 增长 KV Cache
→ 引入 Latent Compression
→ MLA
→ Sparse Selection
→ DSA
→ V4 Hybrid Attention

对于不存在直接结构继承关系的技术，不允许通过动画误导观众。

### 画面质量要求

- 1920×1080，16:9。
- 30 FPS。
- 优先采用有设计感的二维与三维混合视觉。
- 精致字体、清晰排版、统一色彩。
- 适当使用灯光、体积感、景深、镜头运动。
- 用真实的对象变换解释模型计算。
- 动画具有细腻的 easing、stagger 和镜头过渡。
- 镜头之间具有视觉连续性。

### 严格禁止

- PPT 式换页。
- 静态论文截图加旁白。
- 一个标题下面放三个矩形卡片。
- 每个镜头都使用文字渐入渐出。
- 随机粒子和无意义科技背景。
- 用复杂特效掩盖技术解释不足。
- 简陋的方块和圆柱体拼成的低质量三维模型。
- 大段文字停留在屏幕上。
- 只做漂亮的图，而不展示计算过程。

**如果关掉旁白，观众仍应该能看懂主要结构变化。**

## Chapter 1：Prefill 与 Decode

以用户输入一个长 Prompt 为例。

第一阶段：

Prefill

大量输入 Token 可以在模型中并行处理。

第二阶段：

Decode

模型逐步生成新 Token。

必须准确解释：

- Prefill。
- Decode。
- KV Cache。
- Batch Size。
- Arithmetic Intensity。
- Compute-bound。
- Memory-bandwidth-bound。

注意：

Prefill 更容易体现高计算利用率。

低批量 Decode 常常受到权重读取带宽约束。

但具体瓶颈仍然取决于 Batch、序列长度、模型架构和硬件。

不要把所有 Prefill/Decode 工作负载都描述成固定不变的瓶颈。

## Chapter 2：传统 Static Batching

展示四个用户请求：

Request A：生成 20 Tokens。

Request B：生成 100 Tokens。

Request C：生成 50 Tokens。

Request D：生成 200 Tokens。

所有请求组成一个 Batch。

随着部分请求完成，Batch 中出现闲置位置。

新请求仍在队列里等待。

## Chapter 3：Orca 与 Continuous Batching

研究 Orca（2022）的 Iteration-Level Scheduling。

让 Batch 在不同 Decode Iteration 之间动态变化。

完成的请求离开。

新的请求进入。

GPU 的计算槽位得到更高效利用。

重点解释：

- Request-level Scheduling。
- Iteration-level Scheduling。
- Selective Batching。
- Continuous Batching。
- Throughput 与 Latency 的关系。

必须说明：

Continuous Batching 的思想不是凭空由 vLLM 首次发明。

## Chapter 4：KV Cache 成为新的显存瓶颈

展示一个用户请求在 Decode 中不断增加 KV Cache。

然后同时出现数百个用户。

每个请求有不同的序列长度。

显存内部出现：

- 不连续的请求生命周期。
- 内存碎片。
- 未使用的预留空间。
- 不必要的数据重复。

通过空间可视化解释 KV Cache 的动态内存管理问题。

## Chapter 5：vLLM 与 PagedAttention

重点研究 vLLM（2023）。

对比：

传统连续 KV Cache 分配

与

Paged KV Cache 管理

需要借鉴虚拟内存分页的视觉直觉，但真实说明：

- Logical Blocks。
- Physical Blocks。
- Block Table。
- KV Cache Sharing。
- 内存碎片减少。
- 更高有效 Batch 并发。

用一个不断增长的请求展示：

逻辑 Token 顺序保持连续，但 KV Block 可以存放在不同物理显存位置。

重点解释：

为什么减少内存浪费可能带来更高吞吐？

为什么 PagedAttention 不是简单地“把 KV Cache 放进 CPU 内存”？

不能错误地把分页机制与 CPU Offloading 混淆。

# 三、最重要的技术区分

整部视频必须反复区分以下概念。

## 1. Pretraining vs Post-Training

预训练主要通过大规模数据学习语言和世界知识。

后训练则通过指令数据、偏好数据、奖励和交互反馈塑造模型行为。

但这不意味着预训练不能提升推理能力，也不意味着后训练可以无限创造新知识。

## 2. SFT vs Preference Optimization

SFT 学习示范数据中的目标输出。

Preference Optimization 利用回答之间的偏好关系调整模型分布。

不能将 DPO 简单描述为“在 Chosen 上做 SFT”。

## 3. Reward Model vs Verifiable Reward

Reward Model 通常从偏好数据学习近似评分。

Verifiable Reward 可以依据数学答案、代码测试、环境状态等规则产生反馈。

二者具有不同的适用条件和局限。

## 4. PPO vs DPO vs GRPO

PPO：

通过在线采样、奖励与优势估计优化策略，通常配合 Critic / Value Model。

DPO：

通过离线偏好数据以及隐式奖励表示构造直接优化目标，不需要传统 PPO-RLHF 的完整在线训练循环。

GRPO：

通过同一 Prompt 的一组输出构造相对优势，减少对独立 Critic 的依赖。

三者不是简单的前后三代替代关系。

## 5. GRPO vs DAPO vs GSPO

必须依据原始公式展示关键区别。

不能只画三张完全相同的训练流程图。

尤其需要对比：

- Advantage 的计算。
- Importance Ratio 的粒度。
- Clip 的位置和方式。
- Token / Sequence Loss。
- Prompt Group 的筛选。
- 长输出对梯度的影响。
- 是否需要 Reference Policy。
- 不同实现中的归一化与 KL 选择。
- 训练稳定性。
- MoE RL 的特殊问题。

必须以论文具体算法版本为准，不能把某个开源框架的默认配置当成算法唯一标准。

# 九、第六幕：Agentic RL——Agent 能否通过行动反馈真正学习？

时间：17:00–20:30。

这是技术层面的最终高潮。

## Chapter 1：Prompt Engineering 的局限

展示一个基于固定模型和 Prompt 的 Agent。

它可以通过规划、工具和反思改进任务执行，但模型权重通常没有变化。

对于复杂任务，它仍可能反复出现相似的错误。

提出问题：

“如果我们能利用完整任务执行结果来训练模型，它是否能学会更好的行动策略？”

## Chapter 2：Agentic RL

构建真正的强化学习训练循环：

Environment State
→ Policy
→ Action
→ Environment Transition
→ Observation
→ Reward
→ Policy Optimization

使用一个可复现的小型任务环境。

例如：

Agent 必须找到一份文件、修改其中的代码、运行测试，并通过最终验证。

展示完整 Agent Trajectory：

State 0
→ Action 1
→ State 1
→ Action 2
→ State 2
→ ...
→ Terminal Reward

重点解释：

- Agent Trajectory。
- Multi-turn Interaction。
- State / Action / Reward。
- Terminal Reward。
- Sparse Reward。
- Credit Assignment。
- On-policy / Off-policy。
- Tool-use RL。
- Environment Feedback。

必须展示训练和推理之间的区别。

在训练阶段，环境反馈可以通过优化算法更新模型参数。

在推理阶段，模型使用训练后的策略完成任务。

不能把普通 Reflection 当成 RL Weight Update。

## Chapter 3：Agent Lightning 等技术

研究 Agent Lightning 及其他经核实的 Agentic RL 工作。

解释为什么训练框架开始尝试把：

Agent Runtime。

Environment Interaction。

Trajectory Collection。

Reward Computation。

Policy Optimization。

进行模块化分离。

着重解释：

为什么长轨迹 Agent 的 Credit Assignment 比单轮答案评分更困难？

如果最终任务失败，如何判断究竟是哪一步导致了失败？

为什么工具和环境的状态变化会影响训练数据分布？

## Chapter 4：Evaluation 与可靠性

研究：

AgentBench。

WebArena。

OSWorld。

SWE-bench。

τ-bench。

解释：

- Task Success Rate。
- End-to-End Completion。
- Tool Accuracy。
- Recovery Rate。
- Cost per Successful Task。
- Latency。
- Pass@k / 多次运行稳定性。
- 安全性与权限控制。

展示 Agent 在长任务中可能出现的错误累积。

例如，在一个教学用的独立假设模型里：

如果每一步成功率为 p，且各步骤独立，那么连续 n 步全部成功的概率为 p^n。

用动态曲线展示任务长度增加时的可靠性挑战。

必须标注这只是独立性假设下的简化模型，不代表真实 Agent 的实测成功率。

对任何真实 Benchmark 指标，必须使用同版本、同环境、同任务设置的可比较结果。

不要跨不同年份、不同 Benchmark 直接拼接成虚假的 Agent 能力提升曲线。

九、第六幕：2025–2026，迈向真正统一的多模态智能
时间：18:00–22:00。

优先选取有明确技术细节的代表性架构。
重点讨论五个问题。
1. 更统一的跨模态表示
不同模态能否共享更多计算模块？
哪些层需要模态专用 Encoder？
哪些层适合共享 Transformer？
为什么有些模型仍保留独立的输入和输出模块？
2. 实时音视频交互
展示连续的视频输入与音频输入。
模型需要：
持续获取观察。
维护时间信息。
处理音视频同步。
生成低延迟语音回答。
解释：
Streaming Perception。
Streaming Generation。
Synchronization。
Turn-taking。
Interruption Handling。
3. 长视频与高分辨率输入
随着视频时长和图像分辨率增加：
Visual Token 数量不断增长。
计算量、KV Cache 和延迟可能显著增加。
研究：
Dynamic Resolution。
Token Compression。
Frame Selection。
Temporal Sampling。
Long-context Attention。
跨时间检索。
不得假设单纯扩大上下文窗口就自动解决了长视频理解问题。
4. Spatial Reasoning 与 Embodied Intelligence
模型不仅需要识别：
“这里有一辆汽车。”
还可能需要理解：
“汽车与行人的相对位置是什么？”
“车辆运动方向如何变化？”
“下一时刻可能发生什么？”
进一步引出：
Video Understanding。
Spatial Reasoning。
Vision-Language-Action Models。
Embodied Agents。
但必须区分：
语言中的空间描述能力。
几何和运动推理能力。
真实物理环境中的可靠行动能力。
这些不等于同一种水平的世界理解。
5. 多模态推理与训练
研究：
Multimodal Instruction Tuning。
Cross-modal Alignment。
Multimodal Preference Optimization。
Multimodal RL。
Visual Reasoning。
Audio-Visual Reasoning。
讨论：
为什么模型即使能够感知图像，也可能在视觉推理过程中出现幻觉？
为什么更高的视觉识别准确率，不一定意味着更好的跨模态推理？
为什么真实世界中的时间、空间和因果关系仍然是困难的问题？
